# Travel Map

`Apps/visited-map` is a demo-ready family travel map. The app itself contains
only code; mutable state lives in its app data directory:

- [[.playground/local/visited-map/config.json]] — family membership and optional Google email mapping.
- [[.playground/local/visited-map/data.json]] — visits, wants-to-visit tags, and the generated place lookup.

For a new installation, follow [[Apps/visited-map/SETUP.md]] first. The app
shows a setup notice when `config.json` has no family members.

## Configuration

`config.json` has this shape:

```json
{
  "version": 1,
  "people": [
    {
      "id": "alex",
      "name": "Alex",
      "color": "#3b82f6",
      "short": "A",
      "emoji": "👤",
      "email": "alex@example.com"
    }
  ]
}
```

- `id` is the stable identifier used in `data.json` and by `tag_visit`.
- `name`, `color`, `short`, and `emoji` control the UI.
- `email` is optional. When present, the Google identity integration uses it to
  default the map to that person's view. It is never required to tag someone.
- IDs must be unique. Use lowercase, stable IDs; changing one later requires
  updating that person's IDs in the travel data.

## Data model

`data.json` has:

- `visits.countries` — `placeId` → array of configured person ids.
- `visits.states` — `placeId` → array of configured person ids.
- `wants.countries` — `placeId` → array of configured person ids.
- `wants.states` — `placeId` → array of configured person ids.
- `lookup` — generated by the page: common place names → internal place ids.

Place IDs are derived from the Natural Earth / Atlas data:

- Countries: the numeric ISO id from `world-atlas` (e.g. `"380"` for Italy).
- US states: `US-<state name>` (e.g. `"US-California"`).

The page rewrites the `lookup` table automatically when it loads. Open the
app once after creating the files before using a country name with the agent
tool.

## Mutual exclusivity

“Visited” (`visits`) and “Wants to Visit” (`wants`) are mutually exclusive for
each person and place. Setting one status automatically clears the other.

## How to tag or untag someone

Use the `tag_visit` tool. It accepts a configured person ID and looks up the
internal place ID automatically.

Parameters:

- `place` — Country or US state name, e.g. `"Italy"`, `"Japan"`, or `"California"`.
- `personId` — One of the IDs currently listed in `config.json`.
- `visited` — If true, add the visited tag; if false, remove it.
- `want` — If true, add the wants-to-visit tag; if false, remove it.

Examples:

- Tag a configured person as wanting to visit Japan: `place="Japan"`, `personId="alex"`, `want=true`.
- Mark a configured person as having visited France: `place="France"`, `personId="alex"`, `visited=true`.
- Remove a person's California want: `place="California"`, `personId="alex"`, `want=false`.

If `personId` is rejected, read `config.json` and use one of its current IDs.

## UI behavior

- The map starts zoomed to the world with a Carto basemap.
- A mode toggle switches between **World** (countries) and **US States** (states).
- Filter controls toggle the visibility of visited places, wanted places, or both.
- The person selector defaults to the configured person matching the signed-in
  Google email when one is configured; otherwise it falls back to the last
  chosen person on that device or the family view.
- Selecting **All** opens a detail panel with a status control for every
  configured family member.
- The page and pinboard watch both app-data files, so membership and travel
  changes made by another session appear live.

## Editing by hand

Edit the files under `.playground/local/visited-map/` directly when you need to
make a bulk change. Keep membership in `config.json`; do not add a `people`
array back into `data.json`. After editing membership, reload the app or wait
for its config-file watcher to refresh.
